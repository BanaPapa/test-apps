# PRD · 6. 단지 알림

## 한 줄 요약

관심 단지마다 **"최고가를 넘으면", "새 거래가 생기면", "얼마 아래로 거래되면", "거래가 해제되면"** 같은 조건을 정해 두면, 매일 아침 조건에 맞는 새 신고만 슬랙으로 알려 주는 앱.

## 누가, 언제 쓰나

| 사용자 | 상황 | 원하는 것 |
|---|---|---|
| 매수 대기자 | 목표 단지가 특정 가격 아래로 나오길 기다린다 | 그 순간만 알림, 나머지 날은 조용히 |
| 집주인 | 내 단지 시세가 궁금하지만 매일 찾아보긴 귀찮다 | 새 거래·최고가 경신 알림 |
| 단지 전문 중개사 | 담당 단지의 신고가·해제를 손님보다 먼저 알아야 한다 | 해제 알림까지 |

## 이 앱이 하는 일

1. **조건 만들기(화면)**: 동 → 단지 → 평형을 고르고 조건을 고르면 "가로수힐 84㎡가 [최고가를 넘으면] 알려주세요" 문장 하나가 생긴다. 켜고 끌 수 있다.
2. **설정 파일 만들기(화면)**: 조건들을 `config/alerts.json` 내용으로 만들어 복사하게 해 준다. 사용자는 GitHub 저장소의 그 파일에 붙여 넣는다.
3. **매일 확인(자동)**: GitHub Actions 가 매일 08:00 에 `scripts/daily.ts` 를 돌린다. 지난 확인 때 목록과 비교해 새로 확인된 거래·새 해제를 찾고(국토부 API 에 신고일이 없어 이렇게 한다), 조건에 맞는 것만 슬랙으로 보낸다. 맞는 것이 없으면 보내지 않는다. 해제는 받은 24개월 전체에서 찾는다.
4. **받은 알림 보기(화면)**: 휴대폰 화면 모양으로 지난 알림 기록을 보여 준다.
5. **지금 확인(화면)**: 스냅샷 없이 최근 30일 계약분으로 조건을 시험해 결과를 보여 준다. 원하면 슬랙으로도 보낸다.

판단은 숫자 비교 규칙으로만 한다. 분석 모델(AI)은 쓰지 않는다.

## 하지 않는 것

- 휴대폰 앱 푸시(슬랙 앱이 대신한다), 문자, 카카오톡
- 동 전체 요약(5번 시나리오의 몫)
- 화면에서 GitHub 저장소에 직접 쓰기
- 로그인, 서버 데이터베이스

## 화면

`design/mockup.html` 참고. 왼쪽에 휴대폰 크기의 알림함, 오른쪽에 조건 문장들과 연결 칸.

## 연결

| 무엇 | 필요 | 어디에 |
|---|---|---|
| 공공데이터포털 인증키 | 필요 | 화면(시험용) + GitHub Secret `MOLIT_API_KEY` |
| 슬랙 Webhook | 필요 | 화면(시험 발송용) + GitHub Secret `SLACK_WEBHOOK_URL` |
| GitHub 저장소 | 필요 | 매일 실행용. `docs/AUTOMATION.md` |
| 분석 모델 | 필요 없음 | |
