## 사용자가 "만들어줘", "설치해줘", "진행해줘", "이대로 코딩해줘" 라고 하면

1. 아래 **읽는 순서**대로 문서를 모두 읽는다. 건너뛰지 않는다.
2. `node -v` 로 Node.js 버전을 확인한다. **{{NODE_MIN}} 이상**이어야 한다. 없거나 낮으면 https://nodejs.org 에서 LTS 를 설치하라고 안내하고 멈춘다.
3. `docs/BUILD_PLAN.md` 의 0단계부터 마지막 단계까지 **멈추지 말고** 진행한다. 단계마다 그 단계의 "확인"을 실제로 해 보고, 실패하면 고친 뒤 다시 확인한다.
4. 사람이 직접 해야 하는 일(인증키 발급, 결제 등록, GitHub Secrets 입력)은 그 단계에서 짧게 안내만 하고, **키가 없어도 예시 데이터로 계속 진행한다.** 키가 있어야만 확인할 수 있는 항목은 마지막 보고에 "키를 넣은 뒤 확인할 것"으로 모은다.
5. 끝나면 아래 **마지막 보고** 형식으로 알린다.

중간에 사용자에게 묻는 것은 문서끼리 서로 어긋나거나, 문서에 없는 결정을 해야 할 때만이다.

## 지켜야 할 것

- **제공된 부품은 고치지 않는다.** `lib/molit.ts`, `lib/stats.ts`, `lib/regions.ts`, `lib/sample.ts`, `lib/client.ts`, `lib/constants.ts`, `lib/months.ts`, `app/api/molit/route.ts`{{CORE_EXTRA}} 과 `tests/` 의 기존 테스트, `data/`. 실제 응답으로 검증된 코드다. 꼭 고쳐야 한다면 먼저 이유를 사용자에게 말한다.
- **범위를 넓히지 않는다.** PRD 의 "하지 않는 것"은 만들지 않는다. 더 좋아 보이는 기능이 떠올라도 마지막 보고에 제안으로만 적는다.
- **패키지를 더 설치하지 않는다.** STACK.md 1절 밖의 라이브러리가 필요해 보이면 먼저 묻는다.
- **키를 파일에 쓰지 않는다.** 인증키·API 키·Webhook 주소는 화면 입력(localStorage), `.env.local`, GitHub Secrets 에만 둔다.
- **문서가 코드보다 우선한다.** 문서와 다르게 만들어야 할 이유가 생기면 그렇게 하기 전에 사용자에게 알린다.
- 우선순위: 시나리오 문서(PRD·FSD·DESIGN·BUILD_PLAN) > STACK.md > 일반적인 관례.
